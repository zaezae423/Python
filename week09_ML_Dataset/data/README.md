# 주조 품질보증 AI 데이터셋 안내

이 데이터셋은 다이캐스팅 공정에서 수집한 공정 조건, 센서 측정값과 제품의 품질검사 결과로 구성되어 있습니다. 공정·센서 값에 따라 제품이 양품인지 불량인지 예측하거나, 어떤 불량이 발생했는지 분석하는 데 사용할 수 있습니다.

## 데이터의 기본 단위

- 전체 데이터는 7,535개의 행과 57개의 열로 구성되어 있습니다.
- 한 행은 다이캐스팅 설비의 한 번의 `Shot`에 해당합니다.
- 한 번의 Shot에서 `Cavity 1`과 `Cavity 2` 제품이 하나씩 생산됩니다.
- 각 행의 공정·센서 값은 두 캐비티가 공유합니다.
- 품질 결과는 캐비티별로 구분되어 있으므로 제품 단위로 분석하면 최대 15,070개의 관측치가 됩니다.
- 제품 유형은 `Product_Type`의 `1`과 `2`로 구분됩니다.

데이터 열은 다음 세 종류로 나뉩니다.

| 구분 | 열 수 | 내용 |
|---|---:|---|
| `Process` | 17 | 식별자, 제품 유형, Shot 번호와 설비 공정 조건 |
| `Sensor` | 14 | 용해로, 에어, 냉각수와 공장 환경 측정값 |
| `Defects` | 26 | 13개 불량 유형에 대한 두 캐비티의 검사 결과 |

## Process 변수

| 변수 | 설명 | 사용 시 주의사항 |
|---|---|---|
| `id` | 각 데이터 행을 구분하는 값 | 모든 행에서 고유하지만 값의 생성 규칙은 제공되지 않음 |
| `Product_Type` | 제품 유형 | `1`, `2`를 연속된 크기가 아닌 범주로 해석 |
| `Shot` | Shot 번호 | 데이터 전체에서 반복되므로 고유 식별자가 아님 |
| `Velocity_1`, `Velocity_2`, `Velocity_3` | 용탕 투입 단계별 속도 | 연속형 공정 변수 |
| `High_Velocity` | 고속 구간 속도 | 연속형 공정 변수 |
| `Cylinder_Pressure` | Shot을 위한 실린더 압력 | 수치형 공정 변수 |
| `Rapid_Rise_Time` | 실린더 압력 상승 시간 | 연속형 공정 변수 |
| `Biscuit_Thickness` | 주조 비스킷 두께 | 수치형 공정 변수 |
| `Clamping_Force` | Shot 시 금형을 밀어주는 힘 | 수치형 공정 변수 |
| `Cycle_Time` | 제품이 나오기까지 걸린 전체 시간 | 제품 유형에 따라 분포가 달라질 수 있음 |
| `Pressure_Rise_Time` | 주조 압력 상승 시간 | 연속형 공정 변수 |
| `Casting_Pressure` | Shot 시 주조 압력 | 수치형 공정 변수 |
| `Spray_Time` | 전체 스프레이 작업 시간 | 연속형 공정 변수 |
| `Spray_1_Time`, `Spray_2_Time` | 단계별 스프레이 작업 시간 | 연속형 공정 변수 |

변수의 측정 단위는 데이터에 별도로 제공되지 않습니다. 변수명만 보고 임의로 단위를 확정하지 마십시오.

## Sensor 변수

| 변수 | 설명 |
|---|---|
| `Melting_Furnace_Temp` | 알루미늄 용해로 온도 |
| `Air_Pressure` | 에어 압력 측정값 |
| `Air_Pressure_Min`, `Air_Pressure_Max` | 에어 압력의 하한·상한 값 |
| `Coolant_Temp` | 냉각수 온도 측정값 |
| `Coolant_Temp_Min`, `Coolant_Temp_Max` | 냉각수 온도의 하한·상한 값 |
| `Coolant_Pressure` | 냉각수 압력 측정값 |
| `Factory_Temp` | 공장 온도 측정값 |
| `Factory_Temp_Min`, `Factory_Temp_Max` | 공장 온도의 하한·상한 값 |
| `Factory_Humidity` | 공장 습도 측정값 |
| `Factory_Humidity_Min`, `Factory_Humidity_Max` | 공장 습도의 하한·상한 값 |

`Min`과 `Max` 열 중 일부는 데이터 전체에서 값이 변하지 않습니다. 실제 측정 구간의 최솟값·최댓값이 아니라 설비 또는 센서에 설정된 기준값일 수 있으므로 다른 측정값과 구분하여 해석해야 합니다.

## Defects 변수

각 불량 유형에는 `_1`과 `_2`가 붙은 두 개의 열이 있습니다.

- `_1`: Cavity 1에서 생산된 제품의 검사 결과
- `_2`: Cavity 2에서 생산된 제품의 검사 결과

| 변수 | 의미 |
|---|---|
| `Short_Shot` | 미성형: 캐비티가 완전히 충진되지 않은 불량 |
| `Bubble` | 기포 |
| `Exfoliation` | 박리: 제품 표면이 벗겨지는 현상 |
| `Blow_Hole` | 기공: 주물 내부에 생긴 중공의 구멍 |
| `Stain` | 얼룩 |
| `Dent` | 찍힘 |
| `Deformation` | 변형 |
| `Contamination` | 오염 |
| `Impurity` | 이물 |
| `Crack` | 균열 또는 뜯김 |
| `Scratch` | 스크래치 |
| `Buring_Mark` | 소착 |
| `Inclusions` | 개재물: 용탕에 섞인 불순물 관련 결함 |

`Buring_Mark`는 데이터 원본에 사용된 변수명입니다. 일반적인 영어 철자는 `Burning_Mark`이지만 데이터를 다룰 때는 원본 이름을 사용해야 합니다.

## 품질 결과 해석

불량 열은 기본적으로 다음과 같이 해석합니다.

- `0`: 해당 불량이 발생하지 않음
- `0보다 큰 값`: 해당 불량이 발생함

대부분의 값은 `0`과 `1`이지만, 실제 데이터의 일부 행에는 `2` 또는 `3`이 포함되어 있습니다. 이 값의 별도 의미는 정의되어 있지 않으므로 이진 품질 판정에서는 `0`과 `0보다 큰 값`으로 구분하는 것이 안전합니다. 원본 값은 보존하고 어떤 규칙으로 변환했는지 기록해야 합니다.

하나의 제품에 두 가지 불량이 동시에 표시된 경우도 있습니다. 따라서 원본 품질 결과는 여러 불량을 동시에 가질 수 있는 멀티레이블 데이터입니다.

분석 목적에 따라 다음과 같이 목표값을 구성할 수 있습니다.

- 이진분류: `Good`과 `Defect`
- 단일 다중분류: 대표 불량 한 개를 선택하여 분류
- 멀티레이블 분류: 13개 불량 유형을 각각 예측

단일 다중분류를 사용한다면 여러 불량이 동시에 발생한 제품에서 어떤 불량을 대표값으로 선택할지 먼저 정해야 합니다. 주요 불량 우선, 심각도 우선 또는 현장 업무 기준과 같이 일관된 규칙을 사용하십시오.

수업에서 불량 종류를 단순화할 때는 다음 6개 클래스로 묶을 수 있습니다.

| 번호 | 클래스 |
|---:|---|
| 0 | Good |
| 1 | Short_Shot |
| 2 | Bubble |
| 3 | Exfoliation |
| 4 | Blow_Hole |
| 5 | Etc: 나머지 불량 |

## 데이터 사용 전 확인사항

### 결측치

- 90개 행에서 공장 온도·습도 관련 6개 센서 값이 동시에 누락되어 있습니다.
- 누락된 행은 모두 `Product_Type`이 2인 데이터입니다.
- 결측 행을 모두 제거하면 7,445개 행이 남지만 특정 제품 유형의 데이터만 제거되어 표본 편향이 생길 수 있습니다.
- 결측치 삭제와 대체 방법을 비교한 뒤 선택해야 합니다.

### 값이 변하지 않는 변수

- `Air_Pressure_Min`
- `Air_Pressure_Max`
- `Coolant_Temp_Min`
- `Coolant_Temp_Max`

위 변수들은 데이터 전체에서 값이 하나뿐입니다. 공장 온도·습도의 `Min`, `Max` 변수도 결측치를 제외하면 값이 변하지 않습니다. 이런 변수는 현재 데이터 안에서 품질을 구분하는 정보를 제공하지 않으므로 모델 입력에서 제외할 수 있습니다.

### 변수명 공백

원본의 다음 변수에는 앞뒤 공백이 포함되어 있습니다.

- `Biscuit_Thickness `
- `Clamping_Force `
- ` Pressure_Rise_Time`

분석 전에 변수명의 앞뒤 공백을 제거해야 합니다.

### 식별자와 반복 데이터

- `id`는 모든 행에서 고유합니다.
- `Shot` 번호는 반복되므로 고유키로 사용할 수 없습니다.
- 동일한 공정·센서 조건이 반복되는 행이 있지만 반복 생산의 결과일 수 있으므로 단순 중복 오류로 판단하여 삭제하면 안 됩니다.
- `id`와 `Shot`은 물리적인 공정 조건이 아니므로 일반적인 품질 예측 입력에서는 제외하는 것이 안전합니다.

### 캐비티 단위 분석

캐비티별 제품 데이터로 변환하면 하나의 원본 행이 Cavity 1과 Cavity 2의 두 행으로 나뉩니다. 이 두 행은 동일한 공정·센서 값을 공유하므로 학습용과 평가용 데이터에 서로 나뉘면 데이터 누수가 발생할 수 있습니다.

두 캐비티 제품이 항상 같은 학습 또는 평가 그룹에 포함되도록 원본 `id`를 기준으로 데이터를 분할해야 합니다.

### 전처리와 불균형 처리

- 결측치 대체, 변수 선택과 값 변환 기준은 학습 데이터에서만 결정해야 합니다.
- 오버샘플링은 학습용 데이터에만 적용해야 합니다.
- `Product_Type`과 캐비티 번호는 범주형 변수로 처리해야 합니다.
- 원본 데이터를 직접 수정하지 말고 전처리된 데이터는 별도로 관리해야 합니다.
